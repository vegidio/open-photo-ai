## Why

OPAI still installs models with its own pipeline: about 3,000 lines of transfer, resume, hash checks, install records
and engine discard in `deps/install.rs` and `deps/manifest.rs`, plus a three-source listing in `deps/model/` (live
Hugging Face tree, a cached `.listing.json`, and a `published.json` compiled into the binary and regenerated by hand).
Slices 1 and 2 moved everything else onto `rust-sak`'s `ai` feature. Models are the last copy of that infrastructure in
OPAI, and the bare-file half of the pipeline survives only for them.

This is **slice 3 of 3** of the `adopt-rust-sak-ai` series:

1. `adopt-rust-sak-ai-1-deps` (done): runtime and NVIDIA installs, GPU selection, library path and runtime load.
2. `adopt-rust-sak-ai-2-sessions` (done): session building, provider options, the ladder and tuning.
3. **`adopt-rust-sak-ai-3-models`** (this change): model downloads, on a generic Hugging Face file installer added to
   `rust-sak`'s `ai`.

User-visible behaviour stays the same, with three exceptions that the delta specs state. A model that was already
installed is adopted in place, with no re-download. A launch with no network uses installed models as they are.
And the listing compiled into the binary is gone.

## What Changes

**In `rust-sak` (`ai` feature), released under a new tag before OPAI moves:**

- A **file installer**. The caller names a Hugging Face folder, a selection of its files (exact names, or every file
  starting with a prefix), and a destination folder. It installs those files into the folder: resumable, verified
  against the hash the API reports, reported through the existing `Event`s, and serialised by the existing
  per-folder lock.
- A **folder listing** read once (the revision resolved to a commit, then every page listed) and passed to each
  install, so a caller with many installs in one folder pays for one read.
- **Republish-aware current check.** Unlike the archive installer, where a folder only ever holds one version, a file
  here may be republished at the same path. With a listing, an install is current only when the recorded hash of every
  file equals the listing's hash and the file is still on disk at its recorded size. Without a listing, an intact
  install is used as it is and reported as such, and a missing one fails.
- **Adopt in place.** A selected file already in the folder at the listed size, with no record, is hashed. When it
  matches it is kept rather than downloaded again.
- **Derived folders.** The caller can name folders computed from the files. They are emptied when the files are
  replaced, inside the same install, after the old record is deleted and before new bytes move in, and left alone
  when the install was current.
- **Trust local files.** An option under which a folder holding every selected file is used as it is. Its identity
  is a stamp over each file's name, size and modification time. The record says it was trusted, so an install without
  the option never reads it as current.
- An **outcome** for each install: installed, current, adopted, used offline, or trusted. A new `Failure` for a
  selection the listing names no file for.

**In Open Photo AI:**

- `deps/model::install` becomes a call to `rust-sak`'s file installer: folder
  `https://huggingface.co/vegidio/open-photo-ai/tree/main/models`, selection prefix `<artifact>.onnx` (so a sibling
  `.onnx.data` is found from the listing as today), destination `models/<artifact>/`, and derived folder
  `engines/<artifact>/`. Models stay where they are: `<config>/io.vinicius.opai/models/<artifact>/`.
- The listing is read at most once per process, on the first model acquisition and never during `initialize`, as
  today. If that read fails, later acquisitions of installed models in the same process skip it.
- **Removed:** the cached `models/.listing.json`, the compiled-in `published.json` and its generator, `deps/install.rs`,
  `deps/manifest.rs`, `deps/release.rs` and `deps/model/manifest.rs`. Install records (`record_ended`) and the
  `Reporter` stay in OPAI, driven from `rust-sak`'s events and outcome.
- **On disk:** each model's `.manifest.json` is replaced by `rust-sak`'s record at the first acquisition after
  updating. The files themselves are hashed and adopted, not downloaded again. The orphaned `models/.listing.json` is
  deleted best-effort on initialize (TODO-marked for removal).
- `ModelTrust::LocalFiles` maps onto the trust option. The `warn` naming the model stays in OPAI. `ModelTrust` keeps
  its public shape, so `perf --skip-verify` is unchanged.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `model-install`: hashes come from the live listing alone. The cached copy and the compiled-in manifest are gone.
  An installed model is used as it is when the listing cannot be read. An install from an earlier release is adopted
  by hash, not downloaded again. The runtime under trust is verified against its published hash, not a pinned one.
- `logging`: the "fallback source" requirement, which covered the cached and compiled-in listings, is replaced by one
  covering the single fallback left: installed models used without the listing.

## Impact

- **Crates:** `opai` only for logic (`deps/`, `sessions/mod.rs`'s install call and test seam, `progress.rs`,
  `setup.rs`'s `record_ended` import, `lib.rs` cleanup). `gui`, `cli` and `perf` take the `rust-sak` tag bump and
  nothing else. No front-end logic.
- **What `rust-sak` already has:** `hf::Hub` (resolve, paged `list`, `url`), `hf::Hash::verify_file`, `fetch`'s
  resumable downloads, the per-folder lock, the marker, `Event`/`Phase` and `InstallError`/`Failure`. The archive
  installer cannot install bare files into a caller-chosen folder. It treats a present install as current without
  consulting the listing. And it has no adopt, derived-folder or trust behaviour. Those are added there, as general
  pieces any app installing models from Hugging Face needs, not in OPAI.
- **Dependencies:** a new `rust-sak` tag in `opai`, `gui`, `cli` and `perf` together. No new crates.
- **Network:** same host and folder as today. One listing read per process that acquires a model.
- **Disk:** no re-download. The first acquisition of each installed model after updating hashes its files once
  (a few seconds for the largest, about 1.7 GB).
- **Estimated tasks:** 12.
