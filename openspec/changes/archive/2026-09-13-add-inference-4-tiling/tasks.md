## 2. Pixels in, pixels out

- [x] 2.1 Add `inference/pad.rs` mirroring a region's edge pixels outwards to a requested shape, repeating the outermost pixel where the extension is wider than the region has pixels to mirror; verify tests cover a padded region's centre being the original untouched, each edge being the mirror of the rows or columns beside it, a region a few pixels across padded to a full tile reading nothing from outside itself, and a zero-width pad returning the region unchanged (design.md - D3, spec: *A region of pixels becomes the tensor a model reads*)
- [x] 2.2 Add `inference/tensor.rs`'s sampler over a `DynamicImage`: borrowed and directly indexed for `Rgb8`, `Rgba8`, `Rgb16` and `Rgba16`, and converted once through `to_rgba16()` and owned for every other variant, presenting one 16-bit RGB triple per pixel with straight alpha premultiplied against black; verify tests cover a 16-bit source reporting values `DynamicImage::get_pixel` would have narrowed, an 8-bit source widening exactly (255 to 65535), a `Luma16` source going through the owned path with its precision intact, and a half-transparent pixel sampling as premultiplied (design.md - D4, D5)
- [x] 2.3 Add the image-to-CHW conversion writing into a caller-supplied buffer: three planes in R, G, B order, normalised to `[0, 1]` or `[-1, 1]` as asked, over a named region of the source; verify tests cover both normalisations landing on the documented endpoints, the planar layout being channel-major rather than interleaved, a buffer of the wrong length being rejected rather than partly written, and an 8-bit and a 16-bit version of one picture producing values that agree to within the 8-bit source's own quantisation (design.md - D4)
- [x] 2.4 Add the `Channel` trait over `u8` and `u16` and the CHW-to-image conversion writing into a caller-supplied `ImageBuffer<Rgb<T>>`, reversing either normalisation and clamping out-of-range values to the channel's extremes; verify tests cover one model output decoded at both depths describing the same picture, a value above the range clamping to the maximum and one below it to zero rather than wrapping, and the result carrying no alpha channel (design.md - D5, D6)

## 3. Putting a tile into the picture

- [x] 3.1 Add `inference/blend.rs`'s ramp weight — a raised cosine with the half-pixel offset that keeps the first weight strictly positive, and 1 once past the band or for a zero-width band; verify tests cover the curve being monotonic across a band, the first weight being above zero rather than exactly zero, the last approaching 1, and a zero width giving 1 everywhere (design.md - D6)
- [x] 3.2 Add the tile blend, generic over `Channel`, ramping each edge that meets an already-written neighbour over the overlap that edge actually has, writing an edge with no neighbour at full strength, multiplying both weights where a pixel lies in two bands, and clamping a band wider than half the tile; verify tests cover a flat tile blended over a differently-coloured background across a 120-pixel seam leaving no adjacent-column step, the first tile of a row being written unchanged, a corner being weighted by both axes, and the same assertions holding at 16 bits as at 8 (design.md - D6, spec: *Overlapping tiles are combined without a visible seam*)

## 4. The driver

- [x] 4.2 Add `run_tiled`, allocating the scratch once — input buffer, output buffer, decoded tile image, sampler — and walking the grid: convert, pad where the region is short of the tile shape, hand the tile to the caller's function, crop the padding back off at the model's scale, blend, and produce a result of the source's dimensions times that scale; verify tests over an arithmetic tile function cover a multi-tile image reproducing its input through an identity function, a scale of 4 producing four times the dimensions, an image smaller than one tile losing its padding from the result, and the scratch being allocated once however many tiles run (design.md - D2, D7)
- [x] 4.3 Add the refusals and the reporting: a zero-area image refused before any buffer is allocated, progress advancing by one tile's share and snapping to exactly 1 at the end with the initial 0 left to the caller, the cancellation closure consulted before each tile, and a failing tile failing the whole run with no image returned; verify tests cover each of the three zero-area shapes refusing rather than returning a blank image, progress never decreasing and ending at exactly 1 across four hundred tiles, a cancellation partway through returning cancelled with no image, and a tile failure returning no image and naming the tile (design.md - D8, D9)
