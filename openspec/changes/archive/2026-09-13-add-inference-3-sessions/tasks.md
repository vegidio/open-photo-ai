- [x] 2.4 Add the CPU fallback: a build that fails with providers attached re-enters the cache under the CPU key rather than building directly, and the handle carries the requested provider beside the one it was built on; a failure that is not about building the session is not retried; verify tests cover a downgrade succeeding and reporting both providers, a second request for the same model reusing the CPU session already filed rather than rebuilding it, a request for a different model still attempting its provider, and an unreadable model file failing without a CPU attempt (design.md - D6)

## 3. The resident session cache

- [x] 3.1 Add `sessions/mod.rs` with `SessionCache<S>` keyed on the artifact and the resolved provider, handing out an `Arc`-backed handle whose `Drop` stamps the entry as last used, plus the call that releases every resident session at once; verify tests over a fake session cover a repeat request being served the same session, two providers giving two sessions, a handle outliving the entry's removal from the cache and the next request getting a fresh one, and clearing returning without waiting on a session still held (design.md - D4)
- [x] 3.2 Single-flight the build per key, so concurrent requests for one model open it once and a failed build fails every request waiting on it rather than each starting its own; verify tests cover several concurrent requests producing exactly one build, all of them being served that session, and a failing build failing every waiter with no second attempt (design.md - D5)
- [x] 3.3 Add the sweep, taking the cutoff as a parameter and releasing only entries nothing holds, and the background task that calls it with a 15-minute idle interval; verify tests cover an entry unused past the cutoff being released, one used since it surviving, one currently held surviving whatever its timestamp, and that a handle's release restamps the entry so the interval runs from the end of a use rather than its start (design.md - D4, D5)
