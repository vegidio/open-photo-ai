## 1. The key, and the defect it exposes

- [x] 1.1 Fold the resolved `ChannelDepth` into `chain::identity_after`, one hash per operation beside that operation's `cache_tag`, and update `process` to pass the depth it already resolves (design.md - D2). Verify with tests that a chained pair of runs at one depth agrees with a single run over the concatenated operations; that the same chain at 8 and at 16 bits produces different identities; that `OutputDepth::Source` over a 16-bit image and `OutputDepth::Sixteen` produce the **same** identity, because they are the same pixels; that an empty chain is still untouched whatever depth was asked for; and — the counterexample D2 is written against — that `[a]` at 8 followed by `[b]` at 16 does not collide with `[a]` at 16 followed by `[b]` at 16.
- [x] 1.2 Add `memo` to the `rust-sak` feature list in `crates/opai/Cargo.toml`, with a comment recording that it is the module the project context names for this cache, that `memo-async` is deliberately **not** enabled (design.md - D5), and that its disk tier is pure-Rust `redb` so the suite can open a real one. Verify `cargo tree -p opai -d` shows no duplicate of anything it pulls and `cargo build -p opai --locked` succeeds.

## 2. The store

- [x] 2.1 Write `cache.rs`: the public `CacheMode { Disk, Memory, None }`, the 24-hour entry TTL, and the three-way open — `Memo::disk` under `<config>/cache`, falling back to `Memo::memory` at 256 MiB, falling back to no cache (design.md - D1, D4), each constant carrying the reasoning beside it. Verify with tests over a `tempfile` directory that the disk arm opens and reports `Disk`, that a path that cannot be created falls back to `Memory`, that the `None` arm is reachable and serves nothing, and that opening the same directory twice in one process yields one store which still serves what the first opening wrote — which is also the spec's "an application initialized twice" scenario.
- [x] 2.2 Add the encode and decode: PNG at `PngCompression::Fast` through `rust_sak::image::encode_writer`, and `decode_bytes` back (design.md - D3). Verify a round trip preserves dimensions and pixels **exactly** at 8 and at 16 bits per channel — the property that lets a hit be indistinguishable from a miss — and that a 16-bit result does not come back 8-bit, which is the failure a lossy or 8-bit-only codec would have introduced.
- [x] 2.3 Add the get and put over that store, keyed on an identity and written with the TTL, with **every** failure on the read side reported as a miss and **every** failure on the write side discarded (design.md - D10). Verify that a store error, an absent key and an entry whose bytes are not a decodable image are all the same miss; and that both a declined write (`NotAdmitted`, reproduced with a value larger than a deliberately tiny memory budget) and a broken store leave the caller holding its result.

## 3. Wiring it into a run

- [x] 3.1 Put the `Memo` on `Inner`, open it at the end of `Opai::initialize` from `spawn_blocking` — after everything the application cannot run without has succeeded — and add `Opai::cache_mode()` (design.md - D1, D4, D9). Verify that an initialization whose cache directory cannot be opened still succeeds and reports a degraded mode, and that the reported mode is never something a caller can set.
- [x] 3.2 Add `ProcessOptions::cache`, defaulting to `true`, and bind the store once at the top of the run rather than per operation (design.md - D8). Verify that `ProcessOptions { cache: false, ..Default::default() }` compiles and turns it off; that such a run computes every operation, returns the same result a cached run would, and leaves **nothing** stored; and that a run cannot read from the cache and then decline to write back to it.
- [x] 3.3 Read the key before each operation and write the result after it, on the blocking thread the run already uses, with a hit skipping the session acquisition entirely (design.md - D6, D7). Verify against slice 5's fake backend that a second identical run acquires no session and runs no tile; that a chain of two followed by a chain of the same two plus a third runs only the third; that the same operation after a different predecessor is a different entry; and that two runs differing only in depth do not share one.
- [x] 3.4 Keep the whole-chain refusal pass ahead of every cache read (design.md - D7). Verify that a chain whose second operation cannot be served fails even when the first operation's result is already stored — a cache must not turn a bad request into a partial success — and that nothing is installed or opened on its behalf.
- [x] 3.5 Verify by test that a write which fails does not fail the run that produced it: the run returns its result, the following operations of the chain still run, and `InferenceError` gains no variant on the cache's account (design.md - D10).

## 4. What a hit reports

- [x] 4.1 Add `Stage::Cached` and `OperationProgress::cached()`, emitting at that operation's full share through the same path every other report goes through (design.md - D6). Verify that a hit reports `Cached` naming the operation; that `chain_fraction` still never decreases and never returns to the start across a mixture of cached and computed operations; and that a chain whose every operation was cached still ends on exactly 1 rather than never reporting.
